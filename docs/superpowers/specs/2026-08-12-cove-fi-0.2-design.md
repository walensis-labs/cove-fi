## 2. Engine fixes (each ships with a first-principles test)

1. **Income-relative bases replace the hardcoded $225,000.**
   `pct_of_income` rungs and `employer_match_pct` compute against the year's
   active gross income: `sum(income.amount × infl(y) × frac for active
   incomes)`, before pretax deferrals. Closed-form unit test (single income,
   single rung ⇒ exact expected contribution and match).
2. **`coast_multiple` wired.** Replaces the literal `4` in `engine.ts` coast
   detection and `session.ts` `computeCoastYear`. Test: same plan with
   `coast_multiple = 3` coasts no later than with `4`.
3. **`RETIREMENT` sentinel** — exported constant `-2`; TOML loader also accepts
   the string `"retirement"` and maps it. Valid in `income.end` (only there in
   0.2); resolves at run time to `retirement_year - 1` under the EFFECTIVE
   assumptions, so scenario `retirement_year` overrides move income with the
   boundary. Init template and all three examples switch salary `end` to it.
   The `--retirement-year` caveat text shipped in 0.1.0 is deleted from all
   five doc surfaces (limitation gone). Tests: earlier-retirement scenario now
   strictly reduces income in the gap years; sentinel round-trips through
   TOML dump/load.
4. **`Income.taxable` honored** — `taxable: false` streams excluded from the
   ordinary-income tax base (working years and retirement SS-adjacent path).
   Test: two identical plans, one flag flipped ⇒ tax delta equals rate × amount.
5. **Reserved fields stated honestly.** `reduces_by_pretax` and
   `drawdown_order` remain accepted by the loader but are documented as
   reserved/not yet wired (docs/SEMANTICS.md + init-template comments). No
   silent implication they work.

Version note: behavior changes are called out in the changeset ("projection
numbers change vs 0.1.x: income-relative contribution/match bases, coast
multiple honored, RETIREMENT sentinel").

## 3. Validation suite v1 (replaces the PL oracle publicly)

New/promoted tests under `packages/cove-fi/test/validation/`:

- **Closed-form:** single-account compound growth over N years; mortgage
  amortization against the annuity formula (payoff month and total interest);
  today's-$ conversion identities.
- **Conservation/property:** yearly money conservation
  (income = taxes + expenses + contributions + residual, residual bounded);
  taxable basis stays in [0, balance]; determinism (already pinned).
- **Primary-source pins (cited in-test):** RMD divisors vs IRS Pub 590-B
  Uniform Lifetime Table; `IRS_LIMITS_2026` vs IRS 2026 announced limits.
- **Monotonicity:** savings ↑ ⇒ terminal NW weakly ↑; returns ↑ ⇒ NW ↑;
  retirement later ⇒ depletion weakly later; expenses ↑ ⇒ terminal NW weakly ↓.

Docs: `docs/VALIDATION.md` (methodology + citations: Trinity study 1998,
Bengen 1994, Blanchett 2014, Owl/owlplanner methods paper, data provenance
Damodaran + FRED/BLS) and `docs/SEMANTICS.md` (engine rules stated on their
own terms — contribution waterfall is cash-flow constrained, surplus is
spent, nominal internals, flat-tax model with its limitations, drawdown
order, reserved fields). `docs/CALIBRATION.md` and `docs/CONVENTIONS.md` are
deleted (content superseded by these two).

## 4. Monte Carlo (0.2 headline)

- `src/montecarlo.ts`: block bootstrap over vendored annual (real-return
  relevant) series — `data/returns-annual.csv`: year, S&P 500 total return
  (Damodaran, NYU Stern, attributed), CPI-U annual inflation (FRED/BLS,
  public domain), 1928→latest. Block size 5, random restart per block,
  wrap-free sampling from full history.
- Seedable PRNG: own mulberry32 (`Math.random` is not seedable); fixed seed ⇒
  byte-identical results; unset seed ⇒ nondeterministic via
  `crypto.getRandomValues`.
- Per trial: engine run where each year's `ret`/`inflation` come from the
  sampled series. Mechanism: `run` gains an optional third argument
  `rates?: { year: number; ret: number; inflation: number }[]` — additive,
  existing two-arg calls unchanged; when present, per-year rates override
  `assumptions.ret`/`inflation` in growth, income indexing, and expense
  growth. Success = liquid NW > 0 through end year.
- Output: success rate, p10/25/50/75/90 NW trajectories (thinned at the MCP
  edge like projections), trial count, seed used. Default 1,000 trials (<1s).
- Surfaces: `monte_carlo(scenario?, trials=1000, seed?)` MCP tool;
  `cove-fi mc <plan> [--trials N] [--seed S] [--scenario ...]` CLI (+ --json).
- **Benchmark test (flagship):** synthetic retiree, 100% stocks, 30-year
  horizon, 4% initial withdrawal inflation-adjusted ⇒ success rate must fall
  within the published Trinity/Bengen 100%-stock band (test asserts a
  tolerant window, e.g. [0.90, 1.00], seed-fixed; docs/VALIDATION.md explains
  the anchor and cites the papers). Sanity test retained from the old spec:
  success rate moves the right direction as retirement age moves.
- NOT in 0.2: bond series, portfolio mixes, spending-smile-in-MC (0.3+).
